# zmap 設計メモ

## 課題と対象ユーザー(一文)
郵便番号と土地勘を頼りに場所を当てる地図ゲームで遊びたい、GeoGuessr 好き・地理好き・郵便番号の仕組みに興味がある人向け。

## 本命ルール: 「ひろがれ!郵便番号」
1. ラウンド開始時、ランダムな郵便番号を1つ選ぶ。
2. 最初のヒントは、その郵便番号(最も狭い単位)の範囲だけを塗った地図と、その付近の狭い視野のストリートビュー。
3. 一定時間、または「広げる」ボタンごとに、郵便番号を下の桁(文字)から1つずつ外す。
   - 地図のハイライトは前方一致する範囲に広がる(町域 → 市区町村 → 県 → 地方)。
   - ストリートビューの視野(FOV)や表示範囲も段階的に広げる(ズームアウト、周辺パノラマへの移動など)。
4. 好きなタイミングで地図にピンを立てて回答。ヒントが狭い段階で当てるほど高得点。
5. 得点 = 距離(または正解判定)スコア × 段階ボーナス × 難易度倍率。

## 追加モード案
- **絞り込みモード:** 郵便番号を上位桁から1桁ずつ入れ、前方一致の範囲が狭まっていく。少ない桁数で正解地点を特定するほど高得点。
- **逆絞り込みモード:** 下位の桁から入れる。候補地が全国に散らばった状態から、桁を足すごとに減っていく。
- **写真+郵便番号モード:** ストリートビューを見てピンを立て、さらに郵便番号も答える。

## 難易度
「何を当てれば正解か」で5段階を選べる。

| 難易度 | 略称 | 当てる対象 | 正解判定 |
|---|---|---|---|
| Very Easy | VE | 国 | 正しい国を選ぶ |
| Easy | Easy | 県(都道府県・州) | ピンが県内 |
| Mid | Mid | 市(市区町村) | ピンが正解の市区町村内 |
| Difficult | Diff | 街の名前(町域) | ピンが正解の町域内、または町名を選択/入力 |
| Very Difficult | VD | 完全な住所 | 番地・建物まで一致する住所を答える |

- **VD の判定:** 住所を入力(またはピンから逆ジオコーディングした住所)して、正解の住所と構成要素(国・県・市・町域・番地)がどこまで一致したかで判定する。完全一致で満点、一致した要素が多いほど部分点。入力は Places Autocomplete で候補選択を想定。
- 難易度はヒントの出方にも効かせる: 易しいほど最初から広いヒント、難しいほど狭いヒントから始めてペースも遅い。
- 得点倍率は難易度で変える(VE ×1 〜 VD ×5 など)。ランキング・デイリーは難易度別。

## 対応国と「下から外す」階層
| 国 | 名称 | 形式 | 外していく順(狭い → 広い) |
|---|---|---|---|
| 日本 | 郵便番号 | 7桁 NNN-NNNN | 7 → 6 → … → 上3桁(町域 → 市区町村 → 県 → 地方) |
| アメリカ | ZIP code | 5桁(+4) | ZIP+4 → 5桁 → 4 → 3桁 → 1桁 |
| イギリス | Postcode | 例: SW1A 1AA | unit → sector(SW1A 1)→ district(SW1A)→ area(SW) |
| インド | PIN code | 6桁 | 6 → 5 → 4 → 3桁 → 上2桁 → 1桁 |

- イギリスは英字混在のため、桁ではなく階層単位で外す。
- 国は「固定」または「4か国ミックス」を選べる。ミックス時のみ VE(国当て)が成立する。
- 難易度の国ごとの読み替え: Easy=都道府県/州/地方/州、Mid=市区町村/city・county/town/district、Diff=町域/ZIP 地区名/postcode district/PIN 配達区域。

## データ元: Google Maps Platform(API キー)
地図・ストリートビュー・郵便番号の位置・住所はすべて Google Maps Platform を使う。

| 用途 | 使う API |
|---|---|
| 地図表示・ピン回答 | Maps JavaScript API |
| ストリートビュー | Maps JavaScript API(StreetViewPanorama / StreetViewService) |
| 郵便番号 → 位置・範囲 | Geocoding API(`components=postal_code:…|country:…`、`geometry.viewport` / `bounds`) |
| 座標 → 住所・郵便番号 | Geocoding API(逆ジオコーディング) |
| 住所入力(VD) | Places API(Autocomplete) |

### 出題の作り方(案)
1. 国のバウンディング領域内でランダムな座標を生成し、`StreetViewService.getPanorama` でパノラマがある地点だけ採用する(パノラマのない地点は捨てる)。
2. その地点を逆ジオコーディングして、郵便番号・住所の各要素(国・県・市・町域・番地)を取得し、それを正解データとする。
3. 桁を外した段階の範囲は、短くした郵便番号(前方一致)を Geocoding し、その viewport / bounds を地図に塗る。
4. VD では、正解の住所の各要素を比較して判定する。

### 運用上の注意
- API キーは `.env`(`VITE_GOOGLE_MAPS_API_KEY`)から読み込み、**リポジトリにコミットしない**。キーには HTTP リファラ制限と API ごとの制限をかける。
- 課金: Maps JavaScript / Geocoding / Places は従量課金。ラウンドごとの呼び出し数を抑える(出題の事前生成、Geocoding 結果のセッション内再利用)。
- 利用規約: Google Maps Platform の規約により、Geocoding 結果などの長期的なキャッシュ・保存や、ストリートビュー画像の保存・再配布には制限がある。保存できるのは place ID などに限られるため、規約を確認して設計する。
- 範囲は Geocoding の viewport(矩形)が基本。町域の正確なポリゴンは取得できないため、ハイライトは矩形か円で表現するか、境界データを別途検討する(未決)。
- インドはストリートビューのカバー範囲が限られるため、出題前のパノラマ確認が必須。

## 技術スタック(方向性)
TypeScript + Vite + Google Maps JavaScript API。静的ホスティング(サーバー不要)。モバイル対応(郵便番号入力はテンキー)。多言語(日本語 / 英語)。

## MVP の範囲
- 「ひろがれ!郵便番号」モード(ストリートビュー + 桁を外して広がる地図 + ピン回答)
- 日本のみで先行(次に米・英、最後にインド)
- 難易度 Easy〜VD(VE は複数国対応後)
- 5ラウンド制、結果表示とシェア文の生成
- ブラウザのみ(アカウント不要)

## 未解決の疑問
- Geocoding の viewport だけでは町域の形にならない。ハイライトの表現(矩形・円・境界データ併用)をどうするか。
- 同一の郵便番号が複数の町域にまたがる場合、正解範囲をどうするか。
- VD の部分点の配点と、住所表記ゆれ(丁目・番地・建物名)の正規化。
- API 課金の上限管理と、無料枠に収める出題数。
- マルチプレイ(同じ問題で順位競争)の優先度。
